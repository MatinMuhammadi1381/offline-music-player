## Rebuild

From the repository root, restore the locked workspace dependencies once, then run:

```powershell
pnpm install --frozen-lockfile
npm run package:development
```

The package script repeats the tests/typechecks, builds the PWA once through Gradle's `buildPlayerWeb` task, builds/lints the Android debug APK, packages both artifacts into `release-artifacts/development/`, verifies the PWA archive structure, and writes `SHA256SUMS.txt`.

To run only the Android build/lint, use `.\gradlew.bat assembleDebug lintDebug` from `apps/android-file-access-spike`.

## Development artifacts and integrity

Generated artifacts are kept outside source control in the ignored `release-artifacts/development/` directory:

- `offline-music-player-pwa.zip` — static PWA build. Extract its contents to the document root of an approved HTTPS static host. The archive contains only the app shell; it does not contain user audio.
- `offline-music-player-android-debug.apk` — the existing local Android debug APK is from an earlier build and was not regenerated for this PWA-only interface update. GitHub Actions builds a fresh APK with `versionName` `1.6.2` (versionCode 23) on push; it uses the Android debug signing identity rather than a production key.

## Install and recovery

### Android development APK

Enable developer options and USB debugging, connect an Android phone, then run:

```powershell
adb install -r .\release-artifacts\development\offline-music-player-android-debug.apk
```

The APK has no `INTERNET` permission; the UI is packaged in the app. Select audio through the system picker. Track metadata is stored in the WebView's IndexedDB; selected browser file handles are session-only, so reselect audio after an app restart. Export a metadata-only JSON backup to a user-selected location before clearing app data. Importing the backup restores metadata, not audio access.

### iPhone Home Screen PWA

Open the public [GitHub Pages deployment](https://matinmuhammadi1381.github.io/offline-music-player/) in Safari and choose **Share → Add to Home Screen**. Open the app once online to cache the app shell. Selected audio is copied into the app origin's private IndexedDB store and its references are restored when the app reopens. This uses iPhone storage, is not uploaded, and is not part of metadata backups. iOS may still evict browser storage or the user may clear website data; retain original audio. A public deployment or desktop check does not establish long-term iPhone retention.
